# Mabawa Website Modernization

## Goal
Apply the uploaded modernization brief to the existing Mabawa website while preserving working membership, authentication, administrator, content-management and engagement features. Use verified Mabawa information, the official logo, authentic organization imagery and the established green, brown and natural palette.

## Work
1. Audit all current public routes, shared layout, media, content records, forms, administrator tools, database protections and metadata against the brief; retain working functionality and identify only confirmed gaps.
2. Refine the shared design system, navigation, page layouts, responsive behavior and accessibility for a cohesive, editorial, mobile-first experience.
3. Improve the homepage and core organization pages: About, Programs, Projects, Impact, Governance and Contact, keeping claims and project statuses evidence-based.
4. Complete engagement and publishing journeys across Get Involved, Opportunities, Partnerships, Support, News and Stories; add Events, Gallery and individual program/project destinations only where the audit confirms they are missing.
5. Reuse the existing CMS, forms, auth, membership system and administrator dashboard. Make backend or database changes only for demonstrated gaps, retaining protected uploads, role checks, published-only public content, deadline-based opportunity closure and non-transactional support records.
6. Verify navigation, forms, articles, filters, protected routes and responsive layouts; fix discovered errors and provide a page-by-page completion report with unverified or externally blocked items clearly identified.

## Technical details
- Extend the current React/Vite application and shared design tokens; do not replace the application or create parallel content/auth systems.
- Keep the saved official mission, vision, leadership and contact details unless the user confirms an update. The phone-number discrepancy in the uploaded brief is being clarified; retain the current verified site number meanwhile.
- Preserve the existing member registration/card flows, private applicant-document handling, authorization checks and Lovable Cloud data protections.
- Do not invent impact statistics, opportunities, partners, project achievements or event records; do not simulate payments or use AI-generated/stock imagery as Mabawa evidence.

## Validation
- Check route coverage, metadata, image loading, empty/error states, form feedback and mobile/desktop layouts.
- Run relevant existing tests and inspect the current build/runtime signals after changes.
- Verify administrator-only actions only when an authorized account is available; report this limitation rather than claiming untested completion.
